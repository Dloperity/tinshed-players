# Development Evidence Register

This directory holds local evidence used to prepare the A2 configuration-management report. It must not contain student IDs, real credentials, API keys, or real volunteer contact details.

## Naming convention

Use `NN-short-description.png`, where `NN` follows the development sequence. Record the related branch, commit, test command, and Jira issue in the table below when each item is captured.

| File | Evidence | Related branch or commit | Verification status |
| --- | --- | --- | --- |
| `01-branch-baseline.png` | Local feature-branch baseline | `productions-a2` | Pending capture |
| `02-production-edit.png` | Production title edit workflow | `productions-a2` | Pending implementation |
| `03-performance-delete.png` | Performance deletion workflow | `productions-a2` | Pending implementation |
| `04-crew-call-edit.png` | Crew-call update workflow | `productions-crew-call` | Pending implementation |
| `05-pytest-pass.png` | Full pytest result | Relevant commit | Pending implementation |
| `06-pull-request-review.png` | GitHub pull request and peer review | After push | Pending user approval to push |
| `07-actions-pass.png` | GitHub Actions result | After push | Pending user approval to push |

## Capture rules

1. Capture the browser only after the screen shows the completed behaviour.
2. Capture terminal output only after the command and its final result are visible.
3. Do not edit screenshots to imply an action, result, review, or approval that did not occur.
4. Use fictional seed data only. Blur or recapture any accidental personal information before report use.
